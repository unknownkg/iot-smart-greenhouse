# Техническое руководство IoT Smart Greenhouse

Подробные правила эксплуатации, хранения данных и проверки. Краткая презентация проекта — в [README](../README.md).

Учебная SCADA/IoT-панель для наблюдения за микроклиматом теплицы и управления виртуальными устройствами. Система показывает показания датчиков, выполняет ручные и автоматические команды, фиксирует предупреждения и события, строит графики и объясняет оценку риска.

**Все показания и устройства симулируются программно. Реальное оборудование не подключено.** Приложение работает в браузере без серверной логики (backend) и базы данных; состояние сохраняется локально на компьютере пользователя.

## Быстрый запуск на Windows

Понадобятся современный браузер с включённым JavaScript и Python 3 для локального HTTP-сервера. Устанавливать зависимости приложения или выполнять сборку не требуется.

1. Скачайте или распакуйте проект целиком, сохранив структуру каталогов.
2. Откройте PowerShell или терминал в корневой папке проекта — там, где находится `index.html`.
3. Запустите сервер:

   ```powershell
   python -m http.server 8080 --bind 127.0.0.1
   ```

4. Откройте [http://127.0.0.1:8080/](http://127.0.0.1:8080/) и оставьте терминал работающим.

Чтобы остановить сервер, нажмите **Ctrl+C** в его терминале. Если порт 8080 занят, используйте уже работающий сервер этого проекта либо другой свободный порт. Не запускайте второй сервер на занятом порту.

Альтернатива — открыть папку проекта в VS Code и запустить `index.html` через расширение Live Server. Двойной щелчок по HTML-файлу и адрес `file://` не подходят для штатного запуска JavaScript-модулей. Локальный HTTP-сервер только раздаёт файлы: вся логика приложения выполняется в браузере.

## Зоны, датчики и устройства

В системе три независимые зоны: **Томаты**, **Огурцы** и **Зелень**.

Каждая зона содержит шесть виртуальных датчиков:

- температура воздуха — °C;
- влажность воздуха — %;
- влажность почвы — %;
- освещённость — lux;
- концентрация CO₂ — ppm;
- запас воды — %.

В каждой зоне также представлены насос, вентилятор, обогреватель, фитолампа, увлажнитель и форточка. Всего в проекте **18 датчиков и 18 исполнительных устройств**.

Показатель «Датчиков на связи» относится к датчикам. Включение устройства и наличие связи с оборудованием — разные понятия; отдельная модель соединения исполнительных устройств не реализована.

## Симуляция и управление

По умолчанию измерения обновляются каждые **5 секунд**; в настройках доступен интервал от **3 до 10 секунд**. Значения изменяются постепенно в допустимых диапазонах, вода расходуется медленно. Включённые устройства оказывают небольшое учебное воздействие на показания своей зоны. Это упрощённая модель, а не физический расчёт реальной теплицы.

На страницах доступны кнопки «Пауза», «Продолжить» и «Один шаг». Шаг доступен на паузе и выполняет ровно одно обновление. Пауза сохраняется после перезагрузки; пропущенные за время закрытия вкладки измерения не воспроизводятся.

Датчики без связи не получают новые показания и время измерения. Последнее значение помечается устаревшим и не участвует в средних показателях. Переключателя связи датчиков в интерфейсе нет.

Режим выбирается отдельно для каждой зоны:

- **Ручной:** оператор включает и выключает устройства; защитные ограничения остаются действующими.
- **Авто:** устройства управляются по порогам зоны; ручные переключатели заблокированы. Правила применяются сразу при выборе режима или сохранении порогов, в том числе на паузе.

При возврате из автоматического режима в ручной устройства выбранной зоны выключаются. Обычная пауза останавливает измерения, но не выключает устройства и не отключает защитные проверки.

| Устройство | Основное правило автоматического режима |
| --- | --- |
| Насос | Включается при сухой почве и допустимом запасе воды; выключается при достижении верхнего порога влажности почвы или срабатывании защиты. |
| Вентилятор | Включается при превышении верхнего порога температуры. |
| Обогреватель | Включается при температуре ниже нижнего порога. |
| Фитолампа | Включается при недостаточной освещённости. |
| Увлажнитель | Включается при влажности воздуха ниже нижнего порога. |
| Форточка | Открывается при повышенном CO₂; во время автоматического обогрева закрыта. |

Для устойчивого переключения используется гистерезис — разные границы включения и выключения. Текущие условия и причины решений показаны на карточках устройств; пояснения к порогам доступны в настройках.

### Защитные ограничения

- Насос блокируется, если вода находится на критическом пороге или ниже, а также при отсутствии связи с датчиком воды или недостоверном показании. Работающий насос при опасном измерении выключается.
- Автоматический полив требует достоверных показаний воды и влажности почвы. Другие автоматические устройства также не используют недостоверный управляющий датчик.
- Вентилятор и обогреватель не могут работать одновременно. В автоматическом режиме обогрев имеет приоритет над открытием форточки.
- Временная модель, показанная при повреждении сохранённых данных, не считается подтверждением безопасности и не разрешает включать устройства.

**Защита предназначена для учебной демонстрации. Проект не является промышленной системой безопасности и не предназначен для управления реальным оборудованием без отдельной инженерной разработки и проверки.** Пороговые значения — учебные примеры, а не универсальные агрономические нормы.

## Предупреждения, события и аналитика

Предупреждения создаются по фактическим нарушениям порогов, недостоверным данным и блокировке насоса по воде. Вода на критическом уровне, недоступный датчик воды и соответствующая блокировка насоса относятся к критическим условиям. Остальные отслеживаемые нарушения имеют уровень предупреждения. Это учебная классификация проекта.

Непрерывное нарушение обновляет существующее предупреждение. После достоверного восстановления оно автоматически становится устранённым и остаётся в истории. Опасную ситуацию нельзя вручную скрыть как устранённую.

Журнал событий хранит реальные действия оператора, автоматики, защиты, настроек, сценариев и системы. Обычные измерения не засоряют журнал; повторные команды без изменения состояния не создают новые действия.

Аналитика содержит четыре линейных графика — температуру, влажность воздуха, влажность почвы и CO₂ — и столбчатый график текущего запаса воды в трёх зонах. Графики истории используют сохранённые измерения; отсутствующие и недостоверные точки остаются пропусками. Запас воды показывается из текущей модели, а не как дополнительная историческая серия.

Индекс риска рассчитывается по текущим условиям по шкале **0–100** и сопровождается факторами, весами и классом риска. Связанные нарушения одного физического фактора не суммируются повторно. Критическое условие может дать критический класс даже при меньшей сумме баллов. При неполных данных это указано явно; низкое число не подтверждает безопасность.

Система также ищет резкие и длительные отклонения в достоверной истории. Рекомендации объясняют зону, условие, приоритет и возможное действие. Они информационные: не переключают устройства, не заменяют агронома и не гарантируют результат выращивания.

## Сохранение данных

Единое состояние включает зоны, показания и состояния устройств, настройки, паузу, историю измерений, предупреждения и события. Страницы используют общую модель и сохраняют её в **localStorage** браузера.

Размер коллекций ограничен:

| Коллекция | Предел |
| --- | --- |
| История измерений | 240 срезов всей теплицы — около 20 минут при интервале 5 секунд |
| Предупреждения | До 200 записей; при заполнении сначала удаляются старые устранённые |
| Журнал событий | 300 последних событий; интерфейс показывает по 30 |

Перезагрузка страницы сохраняет последние успешно записанные показания, настройки, режимы, паузу и накопленную историю. Несохранённые черновики порогов и фильтры страниц после перезагрузки не восстанавливаются. Работа нескольких активных вкладок с одновременными изменениями не синхронизируется; для демонстрации используйте одну вкладку.

Данные принадлежат текущему браузеру и адресу сайта, включая порт. Другой браузер, другой порт или будущий адрес GitHub Pages имеют отдельное хранилище; автоматического переноса нет.

При запрете или ошибке localStorage приложение сообщает об этом и продолжает работать в памяти. Сохранение между переходами и перезагрузками в таком случае не гарантируется. Повреждённая или несовместимая запись не перезаписывается автоматически.

**«Сбросить демонстрационные данные…» в настройках — отдельное необратимое действие с подтверждением.** Оно возвращает начальную модель и очищает историю проекта; данные других приложений не затрагиваются. Для обычной демонстрации сброс не требуется.

## Демонстрация основных сценариев

Сценарии изменяют учебные показания и добавляют запись в историю. Используйте одну вкладку; при изменённых крайних порогах некоторые сценарии могут быть недоступны.

1. Откройте «Управление», выберите зону, установите режим «Авто» и нажмите «Пауза».
2. Выберите сценарий и нажмите «Применить сценарий». Реакция правил видна сразу.
3. Нажмите «Один шаг», чтобы увидеть влияние включённых устройств на следующее измерение.
4. Просмотрите карточки устройств, предупреждения, журнал событий и аналитику. Перед следующим сценарием вернитесь в «Управление» и проверьте выбранную зону.

| Сценарий | Ожидаемая реакция в режиме «Авто» |
| --- | --- |
| Сухая почва | При достаточном запасе воды включается насос. |
| Критически мало воды | Насос заблокирован; появляются критические предупреждения по воде и защите насоса. |
| Перегрев | Включается вентилятор. |
| Холод | Включается обогреватель. |
| Недостаток света | Включается фитолампа. |
| Низкая влажность воздуха | Включается увлажнитель. |
| Высокий CO₂ | Открывается форточка при отсутствии приоритета обогрева. |

Для демонстрации ручного управления вернитесь в режим «Ручной» и переключите, например, фитолампу. Проверьте запись в журнале. Насос и конфликтующие устройства по-прежнему подчиняются защите.

Кнопка «Восстановить учебные условия» возвращает опорные показания выбранной зоны с учётом порогов. Это **не сброс**: режим, настройки и накопленная история сохраняются. Связь с отключёнными датчиками не восстанавливается. В завершение при необходимости нажмите «Продолжить».

- **HTML5:** восемь отдельных страниц и семантическая разметка.
- **CSS3:** общие стили, Grid/Flexbox, адаптивная графитовая тема и видимый клавиатурный фокус.

- **Git / GitHub:** контроль версий и планируемое размещение исходников; GitHub Pages — будущий статический хостинг.
- **Node.js:** только для автоматических тестов; сайту для работы он не нужен.

Первоначальный проход охватил восемь страниц на ширинах **1920, 1366, 768 и 390 px** — 32 сочетания. После русификации и оформления авторства все восемь страниц повторно проверены на **1366, 768 и 390 px** — 24 сочетания для каждого из этих изменений.

Отдельно осмотрены графики, нижние блоки страниц и таблицы; широкие таблицы прокручиваются внутри своих контейнеров. На коротком экране Sidebar имеет собственную вертикальную прокрутку. В доступных чтениях Console сообщений об ошибках и предупреждениях не обнаружено.

Ограничения проверки:

- Использован настоящий встроенный браузер. Проверки в отдельных установленных браузерах Chrome, Firefox и Safari, а также на реальном телефоне не проводились.
